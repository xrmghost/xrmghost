# ADO-1678 — Refresh xrmghost base-repository README

## Goal

Refresh the `xrmghost/xrmghost` base-repository README so it serves as a differentiated
first-party discovery hub with reciprocal links to the main public XrmGhost surfaces,
appropriate for a GitHub-first landing audience.

## Scope and changes

- Edited `README.md` only (editorial/branding/link-topology, no runtime/infra changes).
- Replaced the tagline: the previous tagline (`Your last broken deploy was the last one.`)
  was found to be a verbatim reuse of the public website (`www.xrmghost.tech`) headline,
  which weakens differentiation per the task's stated risk. Replaced with a distinct,
  on-brand tagline (`Plugins that pass on your machine, not just in a sandbox.`).
- Rewrote body copy to stop echoing the near-duplicate "Deploy. Wait. Test. Fail. Fix.
  Redeploy." framing used on the website/docs, and instead framed the message around why a
  local simulated Dataverse beats a shared cloud sandbox, and the agent-does-the-loop
  narrative — content appropriate for a reader who has landed directly on this repo via
  GitHub (as opposed to the marketing site or docs site).
- Added an explicit "What's public, what isn't" table with reciprocal first-party links to
  sibling public repos in the `xrmghost` GitHub org:
  - `xrmghost-docs` (documentation site source)
  - `xrmghost-skills` (Agent Skills package)
  - `xrmghost-attributes` (.NET attribute library, standalone-usable)
  - `.github` (org-wide profile README)
- Kept/normalized links to `docs.xrmghost.tech` and `www.xrmghost.tech` under a "Go deeper"
  section with labels distinct from the org profile's "Where to go" section (avoided
  reusing the same anchor text/section heading pattern used in `xrmghost/.github`'s
  profile README).
- No assets were added/changed; the existing logo `<picture>` block was left untouched.
